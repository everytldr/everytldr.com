## [Step] MVP Enricher Gemini enrichment client

**맥락:** OpenAI provider 구현 WIP는 stash로 보관하고, 무료 티어로 로컬 검증하기 쉬운 Gemini Developer API 기반 `ArticleEnrichmentClient`를 이번 커밋 단위로 구현했다. Enricher processor, completion service, DB category 기반 선택 흐름은 유지하고 provider adapter만 Gemini로 붙였다.

**구현 범위:**

- `GeminiArticleEnrichmentClient`를 `enricher` profile Bean으로 추가했다.
- `EnricherGeminiProperties`를 추가하고 설정 prefix는 `everytldr.enricher.ai.gemini`로 정했다.
- `enabled=false`를 기본으로 두고, `enabled=true`일 때 API key, base URL, model, timeout, prompt resource가 유효하지 않으면 startup validation에서 실패하도록 했다.
- Spring `RestClient`와 Jackson `ObjectMapper`로 Gemini `generateContent` API를 호출한다.
- API key는 URL query가 아니라 `x-goog-api-key` header로 전달한다.
- `systemInstruction`에는 classpath runtime prompt를 넣고, user message에는 `ArticleEnrichmentRequest`를 compact JSON payload로 넣는다.
- Gemini structured output schema를 요청마다 생성해 `categorySlug.enum`을 현재 DB category slug 목록으로 제한한다.
- 응답의 `candidates[0].content.parts[].text`를 JSON으로 파싱하고, 결과 필드와 `categorySlug` allowlist를 다시 검증한다.
- Gemini `promptFeedback`, candidate 없음, non-`STOP` finish reason, invalid JSON, unknown category는 permanent failure로 분류한다.
- network/timeout, HTTP `408`, `429`, `500`, `503`, `504`는 retryable failure로 분류한다.
- `.env.example`, `application-enricher.yaml`, local `.env`에 Gemini 설정을 추가했고 기본 모델은 로컬 테스트용 `gemini-3.1-flash-lite`로 조정했다.
- `ArticleEnrichmentCategoryOption.from(Category)` factory를 추가해 processor가 JPA entity를 provider 요청 DTO로 변환하는 책임을 DTO 경계에 모았다.
- `ArticlePageContentResolver`에 한영 주석을 추가해 allowlisted HTTP(S) 기사 페이지 전용 resolver라는 의도를 명시했다.

**설계 메모:**

- Java package는 `org.everytldr.enricher.enrichment.gemini`로 두었다. 이미 `enrichment` 아래 provider adapter라서 `ai.gemini`보다 간결하고, 설정 prefix에서만 `ai.gemini`를 사용한다.
- `GeminiArticleEnrichmentUserPayload`는 내부 request와 같은 데이터를 담지만, 외부 API로 나가는 JSON field 이름과 provider boundary를 고정하기 위해 별도 private DTO로 유지했다.
- 현재 카테고리 slug 목록은 processor가 매 요청마다 DB에서 읽는다. 처리량이 커지면 `CategoryOptionProvider`와 Spring Cache/Caffeine 기반 local TTL cache를 먼저 검토하고, Redis cache는 multi-instance invalidation 또는 near-real-time taxonomy update가 필요할 때 도입한다.
- Gemini 요청 body 생성 비용은 HTTP 호출, HTML fetch, AI 모델 latency에 비해 작다. 실제 병목이 확인되기 전까지는 schema/body factory 최적화보다 provider failure handling과 category option cache가 우선이다.
- OpenAI provider selector, Redis Stream, outbox, metrics, token/cost 저장은 이번 범위에서 제외했다.

**테스트 포인트:**

- local HTTP server로 실제 외부 Gemini quota를 쓰지 않고 request path, `x-goog-api-key`, model, system prompt, compact user payload, dynamic `categorySlug.enum`을 검증했다.
- 정상 Gemini 응답이 `ArticleEnrichmentResult`로 변환되는지 검증했다.
- `429`, `5xx`, network timeout 성격 오류는 retryable failure인지 검증했다.
- `401`, invalid JSON, prompt block, no output, non-`STOP` finish reason, unexpected field, unknown category는 permanent failure인지 검증했다.
- Gemini disabled 상태에서는 `ArticleEnrichmentClient` Bean이 등록되지 않고, enabled와 valid settings 상태에서는 단일 Gemini client Bean이 등록되는지 검증했다.
- enabled인데 blank API key이면 Spring context startup이 실패하는지 검증했다.
